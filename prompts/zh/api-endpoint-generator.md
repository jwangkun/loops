# API端点生成器

**分类:** 代码生成与重构
**标识符:** `api-endpoint-generator`
**最大迭代次数:** 8

## 目标

根据接口规范（spec）生成一个完整可用的 API 端点：handler、路由注册与对应的测试，并使检查命令通过。实现须覆盖鉴权/校验、错误响应与约定状态码。

## 适用场景

已持有明确的接口规范（路径、方法、入参、出参、状态码、鉴权）时，端到端生成端点；不适用于规范模糊、需先做探索设计的场景。

## 检查命令

```bash
npm run test:api
```

## 退出条件

- 路由、handler、测试均已生成。
- 端点测试全部通过，检查命令退出码为 0。
- 入参校验与错误状态码符合规范。

## 执行步骤

Step 1: 运行检查命令，捕获输出，确认现有测试结构与端点尚未生成的部分。
Step 2: 对照 spec 列出契约：路径/方法、请求体与查询校验、成功与各错误状态码、鉴权要求；据此规划测试用例。
Step 3: 生成 handler、路由注册与测试，复用项目既有的中间件、错误处理与校验模式。
Step 4: 重新运行检查命令；若仍有用例失败且未达最大迭代次数，回到 Step 2 修正实现或补测试。
Step 5: 若达到最大迭代次数仍有测试未通过，停止并报告失败用例与可疑的规范不一致项，不要放宽断言或注释掉测试。

## 常见陷阱

- 只测成功路径：忽略 4xx/5xx、校验失败与鉴权拒绝，端点形同裸奔。
- 自创错误处理：绕过项目既有错误中间件，响应格式不一致。
- 路由与测试脱节：测试未真正命中新路由，给的是虚假绿色信号。

## 注意事项

- 严格遵循 spec 的状态码与响应结构；发现 spec 矛盾应上报而非自行裁决。
- 鉴权与校验必须显式存在，不能假设上游已处理。
- 不要为了让测试通过而全局 mock 数据库或鉴权层。

## 推荐代理

Claude Code、Cursor、Trae、Windsurf、Cline
