# 授权策略校验循环

**分类:** 后端与API开发
**标识符:** `authz-policy-loop`
**最大迭代次数:** 10

## 目标

确保每个敏感端点在通过身份认证后，都执行了正确的授权检查（基于角色/权限/资源归属）。未授权访问被拒绝并返回 403，授权矩阵测试全部通过。

## 适用场景

当新增了敏感操作端点却未加授权检查，或审计发现存在越权风险（水平/垂直越权）时使用。也适用于上线前的权限加固。

## 检查命令

```bash
npm run test:authz
```

## 退出条件

- `npm run test:authz` 退出码为 0。
- 所有敏感端点在认证之后都有显式授权检查。
- 越权访问（包括水平越权：访问他人资源）测试均返回 403。

## 执行步骤

Step 1: 运行 `npm run test:authz`，记录未授权却可访问的端点、授权缺失的用例以及返回码不符的情况。
Step 2: 审计每个敏感端点，确认在认证之后是否做了授权判断，是否存在水平越权（用户 A 访问用户 B 的资源）或垂直越权（普通用户访问管理接口）。
Step 3: 用最小改动为缺失端点添加授权检查（基于角色/权限/资源所有权），并补齐对应的越权测试用例；不要把授权逻辑与认证逻辑混为一谈。
Step 4: 重新运行检查命令；若仍失败且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代次数仍未通过时停止，汇报剩余越权风险与失败用例，不要无限循环。

## 常见陷阱

- 把"已登录（认证）"当作"已授权"，遗漏真正的授权判断。
- 只防垂直越权，忽略水平越权（用户访问他人资源）。
- 授权检查放在前端或客户端，后端未做校验。
- 用宽松判断（如仅检查字段是否存在）代替精确的角色/所有权校验。

## 注意事项

- 授权检查必须在后端、在认证之后、在业务逻辑之前执行。
- 资源所有权校验要基于不可伪造的服务端数据（如 session 用户 ID）。
- 不要为通过测试而放宽授权规则或注释掉断言。
- 默认拒绝（deny-by-default）：未明确允许即拒绝。
