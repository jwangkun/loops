# 备份例行循环

**分类:** 系统与DevOps
**标识符:** `backup-routine-loop`
**最大迭代次数:** 5

## 目标

备份检查脚本对所有关键数据源报告零失败，且每一份备份的校验和/记录与源数据一致，备份处于健康、可恢复状态。成功意味着不仅作业跑完，而是真正可还原。

## 适用场景

在定期备份窗口、重大变更前后，或当需要确认灾难恢复资产确实可用的任何时刻运行此循环。

## 检查命令

```bash
python scripts/backup_check.py
```

## 退出条件

- `backup_check.py` 退出码为 0。
- 每个关键数据源状态均为 ok/verified。
- 无 missing、stale（新鲜度不达标）或 corrupt 记录。

## 执行步骤

Step 1: 运行 `python scripts/backup_check.py`，捕获完整 stdout、警告行与退出码。
Step 2: 分析失败项 —— 区分备份缺失、过期（freshness 不达标）、校验和不匹配、文件损坏、权限或凭据错误，并定位到具体源。
Step 3: 做最小修复：重新触发对应备份作业、修正路径/凭据或修复权限；切勿通过放宽阈值或删除失败条目来掩盖问题。
Step 4: 重新运行检查；若仍失败且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代仍未通过则停止，列出剩余阻塞项与失败源，切勿无限循环。

## 常见陷阱

- 仅凭退出码 0 判定成功，忽略部分源 stale 或 corrupt 的警告行。
- 备份成功却从未做过恢复演练，真到灾难时才发现不可用。
- 为消除告警而调大 freshness 阈值或跳过源，掩盖真正的备份失败。

## 注意事项

- 永不修改源数据；只触发备份并校正备份流程配置。
- 处理凭据/密钥时遵守最小权限，避免在日志中泄露。
- 删除或覆盖备份前必须确认，避免唯一副本丢失。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
