# 覆盖率直到达标

**分类:** 测试
**标识符:** `coverage-until-threshold`
**最大迭代次数:** 10

## 目标

让测试覆盖率达到配置的阈值（默认 80%），检查命令以退出码 0 通过。提升须来自针对真实未覆盖路径的有效测试，而非降低阈值、排除文件或写无意义的桩测试。

## 适用场景

新增代码或重构后覆盖率低于阈值、CI 因覆盖率门禁失败，需要补齐有价值的测试以达标时。

## 检查命令

```bash
npm test -- --coverage
```

## 退出条件

- `npm test -- --coverage` 退出码为 0。
- 总体覆盖率及各维度（行/分支/函数）均达到阈值（默认 80%）。
- 未达到最大迭代次数上限。

## 执行步骤

Step 1: 运行 `npm test -- --coverage`，捕获覆盖率报告与退出码。
Step 2: 定位最大缺口：找出覆盖率最低的文件与未覆盖的分支/错误处理路径，区分核心逻辑与低价值代码。
Step 3: 为未覆盖的关键分支补写有意义、覆盖真实行为（含边界与错误路径）的测试；严禁降低阈值、在配置中排除文件或堆砌空断言。
Step 4: 重新运行命令；若仍低于阈值且未达上限，回到 Step 2。
Step 5: 若达到最大迭代次数仍未达标，停止并报告剩余缺口（最低覆盖文件、未覆盖分支、预估补测成本）；绝不无限循环。

## 常见陷阱

- 只追求行覆盖：高行覆盖也可能漏掉关键分支与错误路径。
- 写无意义测试：仅调用函数不断言，刷高数字却不防回归。
- 覆盖率为导向而降低标准：为达标排除文件或下调阈值，掩盖真实风险。

## 注意事项

- 不要通过降低阈值或在配置中排除文件来达标。
- 测试须覆盖真实行为与边界/错误路径，并有有效断言。
- 优先覆盖核心业务逻辑，而非追求低价值代码的数字。
