# 仪表盘同步循环

**分类:** 数据科学与分析
**标识符:** `dashboard-sync-loop`
**最大迭代次数:** 5

## 目标

让仪表盘准确反映最新的底层数据与业务指标，消除数据陈旧、查询报错或指标缺失等问题。成功的标志是检查命令无错误退出，且仪表盘上的关键数字与源数据一致。

## 适用场景

当仪表盘刷新失败、数字与源系统对不上、或定时同步中断需要人工介入时使用。不适用于数据源本身尚未就绪的情况。

## 检查命令

```bash
python scripts/refresh_dashboard.py
```

## 退出条件

- 检查命令以退出码 0 完成，无异常输出。
- 仪表盘所有关键指标已更新至最新周期。
- 无残留的失败查询、报错日志或缺失数据块。

## 执行步骤

Step 1: 运行检查命令，完整捕获 stdout/stderr 与退出码。
Step 2: 分析失败原因——区分查询语法错误、字段名变更、缓存未失效、依赖服务不可达，还是数据源尚未更新到最新周期。
Step 3: 做最小修复：修正查询/字段、清除过期缓存、重连数据源；绝不通过注释掉失败指标或硬编码旧值来掩盖错误。
Step 4: 重新运行检查命令；若仍失败且未达到最大迭代次数，回到 Step 2。
Step 5: 若达到最大迭代次数仍未成功，停止并报告剩余阻塞项（具体哪个指标、哪条查询、哪个数据源），不得无限循环。

## 常见陷阱

- 将"缓存命中"误判为数据已更新，实际底层数据早已变化。
- 修复查询时为了让检查通过而调宽时间窗口或放宽过滤条件，掩盖真实数据问题。
- 忽略查询超时与分页截断，导致仪表盘只显示部分数据却无报错。
- 多个仪表盘共用同一缓存键，清缓存时只清了一处。

## 注意事项

- 数据同步前先确认数据源已就绪；数据源未更新时不在此循环范围内。
- 涉及生产数据库的写操作需遵循只读原则，缓存清理动作需确认作用范围。
- 每轮只改一处并记录变更，便于回溯。
