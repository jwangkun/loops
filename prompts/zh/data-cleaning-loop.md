# 数据清洗循环

**分类:** 数据科学与分析
**标识符:** `data-cleaning-loop`
**最大迭代次数:** 8

## 目标

数据质量脚本对当前数据集报告全部规则通过，数据在类型、范围、唯一性与完整性上自洽，且下游建模可直接消费。清洗要保留真实信号，而非仅仅让检查变绿。

## 适用场景

在采集/合并新数据后、建模前，或当数据质量检查出现回归时运行此循环。

## 检查命令

```bash
python scripts/data_quality.py
```

## 退出条件

- `data_quality.py` 退出码为 0。
- 所有质量规则通过。
- 无缺失值、重复行、类型不符或越界记录。

## 执行步骤

Step 1: 运行 `python scripts/data_quality.py`，捕获报告与逐条失败明细。
Step 2: 分析失败 —— 区分缺失值、重复行、类型错误、越界/异常值、编码错误，并定位到受影响的列与行。
Step 3: 做最小修复：按业务规则填充/删除缺失值、去重、修正类型、裁剪异常值；务必保留信号，不可为通过检查而删掉真实数据。
Step 4: 重新运行检查；若仍失败且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代仍未通过则停止，列出剩余失败规则与受影响列，切勿无限循环。

## 常见陷阱

- 一刀切删除异常值，破坏真实分布与模型信号。
- 未分组就直接均值/中位数填充，引入跨类别泄漏。
- 只改数据、不更新清洗脚本，下次重跑时问题原样复现。
- 静默丢弃行却不记录，导致样本量与偏倚无法追溯。

## 注意事项

- 每次清洗操作都要可追溯（记录改了什么），便于回滚与审计。
- 训练/测试切分前完成清洗，避免泄漏；绝不基于目标列推断或填充。
- 删除数据是最后手段，需确认对下游建模的影响。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
