# 代码整洁检查

**分类:** 代码质量  
**标识符:** `de-sloppify-pass`  
**最大迭代次数:** 3

## 目标
确保本次 diff 的代码干净、最小化、无遗留的草稿痕迹。删除所有调试代码、死分支、占位实现和随意命名；lint 与测试保持通过。成功即变更读起来像有意为之的最终代码，而非一次性的临时改动。

## 适用场景
在提交或请求评审前，对最近的一组改动运行此检查，确保没有把草稿代码带入主干。

## 检查命令

```bash
npm run lint && npm test
```

## 退出条件
- 本次 diff 中无调试代码、注释掉的代码、死分支或 `TODO/FIXME` 占位
- `npm run lint` 与 `npm test` 均退出码 0

## 执行步骤
Step 1: 运行检查并捕获输出；同时用 `git diff` 审阅本次未提交的全部改动。
Step 2: 逐项扫描 diff：查找 `console.*`/print 调试语句、硬编码临时值、被注释的代码块、无法到达的死分支、误导性命名、重复或冗余实现。
Step 3: 用最小改动删除或修正每一处：移除调试代码、删除死分支、重命名为清晰名称、合并重复；不要为绕过 lint 而放宽规则。
Step 4: 重新运行 lint 与测试；若仍有问题且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代仍未干净则停止，报告剩余的草稿痕迹清单，不要无限循环。

## 常见陷阱
- 漏掉 `console.log`/print、`debugger`、或仅在本地启用的调试开关。
- 把"暂时先这样"的占位实现当作成品留下，未补真实逻辑或未删除。
- 一次性大范围重命名或重构，超出"最小化"范围，使评审难以聚焦。

## 注意事项
- 仅作用于本次变更，不要顺手重写无关的历史代码。
- 删除代码前确认其确实未被引用，避免误删正在使用的分支或工具函数。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
