# 死代码清理

**分类:** 代码生成与重构  
**标识符:** `dead-code-removal`  
**最大迭代次数:** 5

## 目标
移除仓库中所有未被使用的导出、变量、函数与文件，使死代码分析器报告零死代码，且测试全部通过。每一处删除都经过确认，避免误删通过动态引用使用的代码。成功即代码库不再保留任何确认的死代码。

## 适用场景
重大重构或功能下线后，或定期维护时使用，清理积累的孤儿代码以降低维护成本。

## 检查命令

```bash
npx knip --no-exit-code && npm test
```

## 退出条件
- knip 输出无死代码报告项
- `npm test` 退出码 0

## 执行步骤
Step 1: 运行 `npx knip --no-exit-code` 与测试，捕获分析器的完整输出，整理出待处理的死代码清单。
Step 2: 逐项评估：确认项是否真为死代码，重点排查动态导入、字符串引用的导出、被插件/CLI/配置按名加载的符号、仅由类型推导触发的引用，这些常被误判。
Step 3: 对确认项做最小删除（删除未用导出/变量/函数/文件）；对不确定项保留并记录，绝不靠 `// @ts-expect-error` 或保留空壳来"消除"报告。
Step 4: 重新运行 knip 与测试；若仍有报告项且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代仍未清零则停止，报告剩余项及无法确认的原因（如疑似动态引用），不要无限循环。

## 常见陷阱
- 误删被动态 `import()`、`require()`、字符串属性访问或插件系统使用的导出，导致运行时崩溃。
- 删除后忘记重跑测试，遗留对已删符号的引用。
- 为了让分析器"清零"而用空函数/占位 export 替代删除，反而引入新的死代码。

## 注意事项
- 一次只处理一组相关项，便于在出错时回滚定位。
- 涉及公共 API 或被外部包引用的导出，删除前确认无外部消费者。

## 推荐代理
Claude Code、Cursor、Trae、Windsurf、Cline
