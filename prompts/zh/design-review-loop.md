# 设计审查循环

**分类:** 产品与设计  
**标识符:** `design-review-loop`  
**最大迭代次数:** 8

## 目标
让被审查的设计稿或组件通过 `design_check.py` 的全部检查，包括设计 token 使用、间距规范与无障碍（WCAG）规则。成功意味着检查命令零失败项退出。

## 适用场景
新增或修改 UI 组件、页面改版、引入第三方视觉资源后，提交前用本循环确保设计与系统规范一致。

## 检查命令

```bash
python scripts/design_check.py
```

## 退出条件
- 检查命令以退出码 0 通过，且无任何 warning 或 error。
- 所有 token、间距、对比度、焦点可见性等条目均达标。

## 执行步骤
Step 1: 运行 `python scripts/design_check.py`，完整捕获 stdout/stderr 与退出码。
Step 2: 分析每一条失败项，按类型归类（硬编码颜色、间距偏差、对比度不足、缺少 alt/aria、焦点缺失等），定位到具体文件与行。
Step 3: 做最小改动修复：优先复用既有 design token 与组件，而非新造数值；不得用注释、忽略规则或调宽阈值来掩盖失败。
Step 4: 重新运行检查命令；若仍有失败且未达最大迭代次数，回到 Step 2。
Step 5: 若已达最大迭代次数仍未通过，停止并报告剩余阻塞项（文件、失败原因、建议），不要无限循环。

## 常见陷阱
- 用硬编码十六进制颜色替代设计 token，导致主题切换与一致性检查失败。
- 间距用近似值（如 13px）而非 token 倍数（4/8），触发间距规范告警。
- 对比度仅凭肉眼判断，未达到 WCAG AA（4.5:1 正文）标准。
- 给装饰性图片补 alt 文本，或给功能性图标漏掉 aria-label，造成无障碍误报或漏报。

## 注意事项
- 仅修复检查命令实际报告的失败项，不要顺手重构无关样式。
- 区分真正违规与有意为之的例外；例外须有显式记录，不得静默忽略。
- 不要为了让检查通过而降低阈值或临时关闭规则。
