# 模型训练循环

**分类:** 数据科学与分析
**标识符:** `model-training-loop`
**最大迭代次数:** 20

## 目标

模型在验证集上达到预设准确率/指标目标，且训练与验证指标差距合理、未过拟合，结果可通过固定随机种子复现。达标指真实泛化，而非对评估集的过拟合。

## 适用场景

在数据与特征就绪后、需要迭代调优直到指标达标时运行此循环。

## 检查命令

```bash
python scripts/train.py --validate
```

## 退出条件

- `train.py --validate` 报告验证准确率 ≥ 目标值。
- 训练/验证指标差距在阈值内（无过拟合）。
- 运行使用固定随机种子且可复现。

## 执行步骤

Step 1: 运行 `python scripts/train.py --validate`，捕获训练/验证指标、损失曲线与退出码。
Step 2: 分析差距 —— 训练高验证低为过拟合；两者都低为欠拟合；指标剧烈波动多为学习率或数据问题。
Step 3: 做最小调整：用正则化/early stopping/数据增强缓解过拟合，用增加容量/特征/更长训练缓解欠拟合；每次只改一个变量以便归因。
Step 4: 重新运行验证；若未达标且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代仍未达标则停止，报告当前最佳指标与剩余瓶颈，切勿无限循环或人为调低目标。

## 常见陷阱

- 用测试集调参，造成数据泄漏与虚高的乐观估计。
- 只追单一指标导致其被博弈（如准确率掩盖类别不平衡）。
- 未固定随机种子，结果不可复现、改进无法归因。
- 训练分数漂亮但泛化差，过拟合未被发现。

## 注意事项

- 评估只用验证集；测试集留到最终评估，绝不参与调参。
- 固定随机种子，并提交对应的代码与数据版本以保证可复现。
- 不为通过目标而篡改评估逻辑或采样验证集。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
