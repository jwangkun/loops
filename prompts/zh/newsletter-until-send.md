# Newsletter 直到发送

**分类:** 内容创作与写作
**标识符:** `newsletter-until-send`
**最大迭代次数:** 5

## 目标

让 Newsletter 在发送前通过内容审查且所有链接有效，正文无错别字、无失效链接、无事实错误，并具备纯文本降级版本。成功标志是检查命令无错误退出。

## 适用场景

在 Newsletter 正式发送前进行最终质检时使用；适用于链接校验、内容审阅与格式降级的把关。

## 检查命令

```bash
python scripts/newsletter_check.py
```

## 退出条件

- 检查命令以退出码 0 完成，无错误。
- 所有链接可访问（无 404/超时/重定向至错误页）。
- 内容已审阅：无错别字、无事实错误、无未署名引用；纯文本降级版本已生成。

## 执行步骤

Step 1: 运行检查命令，捕获死链清单与每条内容/格式告警。
Step 2: 分析问题——区分死链（删除/改地址）、重定向异常、错别字、事实性疑点，以及缺少纯文本版本等格式问题。
Step 3: 做最小修复：更新或移除死链、订正错别字、核实可疑事实、补纯文本降级；绝不通过注释或隐藏链接来绕过校验。
Step 4: 重新运行检查命令；若仍有错误且未达到最大迭代次数，回到 Step 2。
Step 5: 若达到最大迭代次数仍未通过，停止并报告剩余死链与待审内容，不得无限循环。

## 常见陷阱

- 忽略纯文本降级，导致在纯文本客户端中链接丢失或排版错乱。
- 用短链/重定向掩盖目标页已失效，检查时看似正常、发送后失效。
- 只校验 HTML 中的可见链接，漏掉按钮、图片 alt 链接与退订链接。
- 修改正文后未同步检查，引入新的死链或错别字。

## 注意事项

- 发送前必须人工最终确认收件人、主题与发送时间。
- 不编造数据或引用；不确定的事实标注来源或删除。
- 每轮修改后重新全量校验，避免引入新问题。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
