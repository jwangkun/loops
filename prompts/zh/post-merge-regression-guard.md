# 合并后回归守卫

**分类:** Pull Request  
**标识符:** `post-merge-regression-guard`  
**最大迭代次数:** 3

## 目标

在每次合并(merge)或变基(rebase)之后立即运行冒烟测试套件，确认主干集成未引入回归。任何失败都必须在继续其他工作之前修复，保证合并后的代码始终处于可发布状态。

## 适用场景

在执行merge或rebase将其他分支并入当前分支之后立即运行。用于在着手新开发前拦住集成回归，避免在坏掉的基础上叠加更多改动。

## 检查命令

```bash
npm run test:smoke
```

## 退出条件

检查命令退出码为0，即冒烟测试套件全部通过。

## 执行步骤

Step 1: 合并或rebase完成后，立即运行检查命令，捕获完整输出与失败用例列表。
Step 2: 对每个失败用例判断根因：是合并引入的回归(语义冲突、漏改调用点)，还是上游有意变更导致旧测试失效。
Step 3: 对回归做最小修复(同步被遗漏的调用点、补回被覆盖的改动)；对有意变更则更新测试期望以匹配新契约，禁止删除断言。
Step 4: 重新运行检查命令；若仍失败且未达3次迭代，回到Step 2。
Step 5: 若3次迭代后仍失败，停止并向用户报告未解决的回归与可能的责任提交，不继续后续开发。

## 常见陷阱

- 合并后不立即测试就开发：在坏主干上叠加改动，把回归埋得更深。
- 把语义冲突当测试bug：误删断言而未真正同步调用点，回归被掩盖。
- 用git checkout --丢弃整段改动来"变绿":连同有效改动一并丢失。
- 只信任merge提示"无冲突"：文本无冲突不代表语义无冲突。

## 注意事项

- 冒烟测试必须覆盖关键路径；若套件过弱，应先补强套件再依赖此守卫。
- 修复优先于新功能；主干红色时禁止在其上开始新开发。
- 若回归来自上游而非本地改动，及时回退或与上游沟通，而非自行消化。
