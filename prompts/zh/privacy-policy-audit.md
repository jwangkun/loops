# 隐私政策审计

**分类:** 安全与合规
**标识符:** `privacy-policy-audit`
**最大迭代次数:** 5

## 目标

使 `python scripts/privacy_check.py` 通过，且仓库中的隐私政策文档与代码实际的数据收集、存储、共享实践完全一致：政策声明的每一类数据都能对应到真实的数据流，实际采集的每一类敏感数据都在政策中如实披露。

## 适用场景

发布前、合规审计前，或数据采集逻辑/第三方 SDK/政策文案发生变更后使用，确保产品行为与对用户的隐私承诺不出现脱节。

## 检查命令

```bash
python scripts/privacy_check.py
```

## 退出条件

- `privacy_check.py` 退出码为 0。
- 政策文档中声明的每类数据采集都能在代码中找到对应实现。
- 代码中实际采集/共享的每类个人数据都在政策中如实披露，无未声明的采集或第三方共享。

## 执行步骤

Step 1: 运行检查命令，捕获输出，记录每个不匹配项（类型：政策有声明但代码无实现 / 代码有采集但政策未披露 / 第三方共享未声明）。
Step 2: 对每个差异定位根因：是代码引入了未声明的采集、还是政策文案滞后、或第三方 SDK 默认上报了额外数据。必要时阅读相关采集点与政策章节。
Step 3: 实施最小且正确的修复：若为代码越界采集则移除该采集或补征同意；若为文案滞后则更新政策章节使其如实描述实践。不得通过"从政策中删除声明"来掩盖未授权的采集。
Step 4: 重新运行检查命令；若仍有差异且未达最大迭代次数，回到 Step 2。
Step 5: 若达到最大迭代次数仍有差异，停止并报告剩余差异、涉及的采集点与第三方，交由人工（工程/法务/隐私负责人）处理，不得无限循环。

## 常见陷阱

- 仅对照政策标题核对，而不阅读采集代码与政策具体章节，会遗漏"名称匹配但含义不符"的差异。
- 第三方分析/广告 SDK 默认采集的设备标识、位置等数据，常被遗漏在政策披露之外。
- 将"未声明采集"通过"删除政策中的相关声明"来让检查通过，属于掩盖而非合规修复。
- 检查脚本只覆盖已知采集点，新增的采集逻辑若未注册可能绕过检查——需结合代码审查。

## 注意事项

- 涉及真实用户数据的未授权采集属于需要人工升级的合规事件，优先由隐私/法务负责人确认处置。
- 不得提供帮助规避隐私检查或弱化用户告知的指导；修复方向是让实践符合承诺，而非让承诺迁就越界采集。
- 修复涉及政策文案变更时，需确保多语言版本同步更新，避免版本间不一致。
