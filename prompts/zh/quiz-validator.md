# 测验验证器

**分类:** 学习与知识管理
**标识符:** `quiz-validator`
**最大迭代次数:** 10

## 目标

确保每个测验题目题干清晰无歧义、有且仅有一个正确答案、干扰项合理可信，校验脚本以零违规通过。成功意味着整套题目可直接发布而无需人工二次修订。

## 适用场景

在生成或导入测验/题库后、正式发布前使用，用于在交付学习者前确保题目质量。

## 检查命令

```bash
python scripts/quiz_check.py
```

## 退出条件

- 所有测验项通过校验，脚本退出码为 0。
- 每题有唯一正确答案与合理干扰项。
- 题干无歧义，选项无重复或逻辑矛盾。

## 执行步骤

Step 1: 运行 `python scripts/quiz_check.py`，完整捕获输出与失败项列表。
Step 2: 逐条分析失败原因——重点排查题干歧义（存在多个合理答案）、干扰项过于明显或与正确答案雷同、缺少答案解析、"以上都是/以上都不是"这类偷懒选项。
Step 3: 做最小修复：重写歧义题干、替换无效干扰项、补全正确答案与解析，绝不靠放宽校验或留 TODO 掩盖问题。
Step 4: 重新运行校验；若仍有失败且未达最大迭代次数，回到 Step 2。
Step 5: 若达到最大迭代次数仍未通过，停止并报告剩余阻塞项（如题目本身有根本性缺陷），不要无限循环。

## 常见陷阱

- 题干存在多个可辩护的答案，导致"正确答案"不唯一。
- 滥用"以上都是/以上都不是"作为凑数选项。
- 正确答案总固定在同一位置（如永远是 B/C），可被猜测。
- 干扰项要么明显错误，要么与正确答案几乎相同，失去区分度。

## 注意事项

- 不要为了让脚本通过而削弱题目难度或删除有价值的题目。
- 修复时保持原题考查的知识点不变，只改表达与选项质量。
- 答案解析应解释为何正确、其他项为何错。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
