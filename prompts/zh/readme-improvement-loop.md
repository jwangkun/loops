# README 改进循环

**分类:** 文档
**标识符:** `readme-improvement-loop`
**最大迭代次数:** 8

## 目标

让 README 通过 lint 且真正对读者有用：安装步骤可跑通、示例可复制执行、功能描述与代码实际行为一致。成功标志是检查命令无错误退出。

## 适用场景

当 README 缺失关键章节、命令示例过时或与现状不符、需要补全并校准时使用。

## 检查命令

```bash
python scripts/readme_lint.py
```

## 退出条件

- 检查命令以退出码 0 完成，无 lint 错误。
- 所有必要章节齐全（简介、安装、用法、许可等，视项目而定）。
- 文档中描述的功能、命令与示例均与代码实际行为一致。

## 执行步骤

Step 1: 运行检查命令，捕获每条 lint 错误与告警及其位置。
Step 2: 分析问题——区分结构缺失（缺章节/缺标题）、内容失真（命令不可跑/参数已变更）、示例不可执行、以及徽章或链接失效。
Step 3: 做最小修复：补章节、校正命令与示例；绝不为了让 lint 通过而描述不存在或计划中尚未实现的功能。
Step 4: 重新运行检查命令；若仍有错误且未达到最大迭代次数，回到 Step 2。
Step 5: 若达到最大迭代次数仍未通过，停止并报告剩余 lint 错误清单，不得无限循环。

## 常见陷阱

- 文档化尚未实现或已移除的功能，造成误导。
- 安装命令在本机能跑但缺前置依赖/未注明运行环境，读者照做失败。
- 示例代码与仓库实际路径、API 不一致，复制即报错。
- 徽章指向已失效的 CI/覆盖率服务，留下断链。

## 注意事项

- 文档内容以代码实际行为为准；有疑问时读源码而非沿用旧描述。
- 不夸大能力，不承诺未来路线图中的功能。
- 修改命令示例时同步验证其可执行性。
