# 发布说明生成器

**分类:** 运营与市场
**标识符:** `release-notes-generator`
**最大迭代次数:** 5

## 目标

从提交历史、合并 PR 与工单中生成结构化的发布说明，覆盖新功能、改进、缺陷修复、破坏性变更与已知问题。所有用户可见变更须准确归类，措辞面向最终用户而非面向代码。

## 适用场景

每次发布（主版本、次版本或补丁）对外发布前使用，确保说明可直接交付并面向客户公开。

## 检查命令

```bash
python scripts/release_notes_check.py
```

## 退出条件

- 检查脚本退出码为 0。
- 说明覆盖自上一版本标签以来的全部合并提交。
- 破坏性变更有显式标注并置顶。
- 无占位符或 TBD 项。

## 执行步骤

Step 1: 运行检查命令，捕获输出与缺失项清单。
Step 2: 比对自上一标签起的提交/PR/工单，定位三类问题：漏写的变更、归类错误的条目、面向代码而非用户的措辞。重点关注破坏性变更是否被错误并入"改进"。
Step 3: 做最小修改：补齐缺失条目、修正归类、重写面向用户的措辞，绝不掩盖或合并真正的破坏性变更。
Step 4: 重新运行检查；若仍失败且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代仍未通过，停止并报告剩余阻塞项（如缺失工单链接、无法判定的归类），绝不无限循环。

## 常见陷阱

- 把破坏性变更默默并入"改进"或"其他"，让用户错过升级风险。
- 照抄提交标题（面向代码的描述）而非翻译为用户能理解的语言。
- 漏掉已合并到发布分支但未打标签的提交。
- 编造材料中并不存在的功能或修复以凑内容。

## 注意事项

- 仅依据可验证的提交、PR、工单撰写，不得臆造功能。
- 破坏性变更必须置顶并给出迁移提示。
- 关键信息缺失（如工单链接）时停止并报告，而非猜测。

## 推荐代理

Claude Code、Cursor、Trae、Windsurf、Cline
