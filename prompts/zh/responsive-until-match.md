# 响应式直到匹配

**分类:** 前端与UI
**标识符:** `responsive-until-match`
**最大迭代次数:** 8

## 目标

让 UI 在所有目标断点（移动、平板、桌面、宽屏）上正确渲染：布局不溢出、内容不截断、交互元素可达且不重叠。成功意味着带 `@responsive` 标记的 Playwright 测试全部通过，而非仅在某一个视口下通过。

## 适用场景

新增或重构布局组件后、调整断点策略时、或在 CI 中需要守住响应式回归时使用。

## 检查命令

```bash
npx playwright test --grep @responsive
```

## 退出条件

- Playwright `@responsive` 套件全部通过（exit 0）。
- 所有目标视口下无布局溢出、内容截断或元素重叠。
- 交互元素在各视口下可见且可点击。

## 执行步骤

Step 1: 运行 `npx playwright test --grep @responsive`，捕获失败用例、失败视口尺寸与断言信息。
Step 2: 逐个分析失败并区分类型：固定宽度溢出、flex/grid 配置不当、媒体查询缺失、触控目标过小，或仅在某断点出现的定位错误。
Step 3: 用流式布局、响应式工具类或正确的断点样式做最小修复；不引入硬编码像素或仅针对单一视口的补丁。
Step 4: 重新运行套件；若仍有失败且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代次数仍未通过，停止并报告剩余失败用例、视口与截图证据，不要无限循环。

## 常见陷阱

- 只在桌面视口调试，遗漏移动端的真实布局问题。
- 用固定 `px` 宽度或 `!important` 强行对齐某一视口，破坏其他断点。
- 忽略触控目标尺寸与可访问性，导致移动端难以点击。
- 修改全局样式未评估对其他页面的连带影响。

## 注意事项

- 仅修复失败的响应式布局，不借机重构无关组件。
- 改动需在所有目标视口手动复核，不能只信单个断点的通过。
- 全局或共享样式改动需评估跨页面影响。

## 推荐代理

Claude Code、Cursor、Trae、Windsurf、Cline
