# 密钥扫描循环

**分类:** 安全与合规
**标识符:** `secret-scan-loop`
**最大迭代次数:** 5

## 目标

使 `npx secretlint --maskSecrets "**/*"` 报告零命中，仓库工作区中不存在任何真实密钥或凭证。发现的密钥必须被轮换/吊销，而非仅从历史中删除。

## 适用场景

提交前、合并前或定期安全巡检时使用；怀疑有凭证被提交到仓库、或新增了涉及密钥的配置/测试夹具时尤其适用。

## 检查命令

```bash
npx secretlint --maskSecrets "**/*"
```

## 退出条件

- secretlint 扫描退出码为 0，无命中项（或仅剩已确认的误报且已加白名单并说明理由）。
- 所有真实命中均已轮换/吊销对应凭证，源代码中的泄露已移除。
- 未通过"删除文件/删除历史"来掩盖真实泄露。

## 执行步骤

Step 1: 运行检查命令，捕获完整输出，记录每条命中的文件、行号、规则与被 mask 后的密钥类型（AKSK、token、私钥等）。
Step 2: 逐条判断命中是否为真实密钥：排除测试夹具、示例值、占位符、已失效或已公开的无害值；对无法确定的项保守判定为真实。
Step 3: 对真实泄露：优先将密钥加入待轮换清单并人工轮换/吊销，再从源码移除（改用环境变量/密钥管理服务）；误报才可加入白名单并附理由。严禁仅删除文件或从 git 历史抹除来"消除"命中。
Step 4: 重新运行检查命令；若仍有命中且未达最大迭代次数，回到 Step 2。
Step 5: 若达到最大迭代次数仍有命中，停止并报告剩余命中、涉及的凭证类型与轮换状态，交由人工安全负责人处理，不得无限循环。

## 常见陷阱

- 测试夹具、文档示例、占位符（如 `xxxx`）常被误报为真实密钥，需逐条甄别而非批量忽略。
- 仅从 git 历史中删除密钥不会撤销泄露——密钥仍可能已被获取，必须轮换/吊销。
- `--maskSecrets` 会遮蔽明文，但仍需根据规则与上下文判断类型与严重性。
- 将真实密钥"降级"为字符串拼接或编码（base64/分片）以绕过扫描，是掩盖行为而非修复。

## 注意事项

- 发现真实凭证泄露时，必须将其视为需要人工升级的事件：轮换/吊销优先于代码清理。
- 不要在提交信息、注释或日志中输出明文密钥；处理命中时也不要把明文复制到任何地方。
- 不得提供帮助隐藏、外传或绕过密钥扫描的指导；白名单仅用于明确无误的误报。
