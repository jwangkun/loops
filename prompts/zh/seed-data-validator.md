# 种子数据验证器

**分类:** 数据库与数据
**标识符:** `seed-data-validator`
**最大迭代次数:** 5

## 目标

确保种子数据能在干净（已重置）的数据库上完整加载，所有外键和引用均有效，且 `test:seed` 断言全部通过。成功意味着任何开发者执行此流程后都能得到一致、确定性的初始数据集。

## 适用场景

项目初始化、CI 流水线、或修改种子脚本/数据库 schema 后，用于验证可重现的种子数据加载。

## 检查命令

```bash
npm run db:seed && npm run test:seed
```

## 退出条件

- `db:seed` 执行退出码为 0，无错误或警告。
- `test:seed` 中每条断言（行数、外键完整性、唯一约束）均通过。
- 重新运行命令结果保持稳定（确定性）。

## 执行步骤

Step 1: 在干净数据库上运行 `npm run db:seed`，完整捕获 stdout/stderr。
Step 2: 若失败，定位根因——常见为外键插入顺序错误、唯一约束冲突、必填字段缺失、或引用了尚不存在的记录。逐项修复，不要用 try/catch 或空数据掩盖错误。
Step 3: 应用最小修复（如调整加载顺序、补全缺失字段、修正 fixture 值）后，运行 `npm run test:seed` 验证引用完整性。
Step 4: 若仍有失败且未达最大迭代次数（5），回到 Step 2 继续定位。
Step 5: 达到最大迭代次数仍未通过时，停止并列出剩余阻塞项；禁止无限循环或跳过检查。

## 常见陷阱

- 外键顺序：未按依赖关系先插入父表，导致引用不存在的记录。
- 非确定性：使用随机值或未固定时间戳，使每次运行结果不同、测试时好时坏。
- 唯一约束：重复种子记录或硬编码 ID 与已存在数据冲突。
- 部分失败被忽略：seed 报错但 exit code 仍为 0，掩盖了真正的问题。

## 注意事项

- 仅修改种子脚本和 fixture，不要改动 schema 迁移或生产代码。
- 每次重跑前先重置数据库，确保环境真正干净，避免残留数据造成假性通过。
- 不要为了通过测试而削弱或跳过断言。
