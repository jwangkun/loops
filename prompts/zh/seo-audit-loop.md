# SEO审计循环

**分类:** 运营与市场  
**标识符:** `seo-audit-loop`  
**最大迭代次数:** 10

## 目标
让目标页面通过 `seo_check.py` 的全部检查，覆盖 meta 标签、标题层级、链接、结构化数据与页面性能。成功意味着检查命令零失败项退出，页面满足可索引性与基本排名要素。

## 适用场景
新页面上线、模板改版、内容大改或收录/排名异常下降后，提交前用本循环确保技术 SEO 基线达标。

## 检查命令

```bash
python scripts/seo_check.py
```

## 退出条件
- 检查命令以退出码 0 通过，且无 error。
- meta、canonical、标题层级、链接有效性、结构化数据、Core Web Vitals 基线均达标。

## 执行步骤
Step 1: 运行 `python scripts/seo_check.py`，完整捕获输出与退出码，记录每条失败的页面与字段。
Step 2: 按影响排序分析失败项（缺失/重复 title 与 description、错误 canonical、断裂链接、跳过标题层级、缺失结构化数据、Core Web Vitals 不达标等），定位到具体页面与标记。
Step 3: 做最小修复：补全或修正单个字段；优先处理影响可索引性与抓取的高影响项，避免关键词堆砌等取巧手段掩盖问题。
Step 4: 重新运行检查命令；若仍有失败且未达最大迭代次数，回到 Step 2。
Step 5: 若已达最大迭代次数仍未通过，停止并报告剩余失败项（页面、字段、原因、建议），不要无限循环。

## 常见陷阱
- 关键词堆砌 title/description，触发堆砌判定且降低点击率。
- 忽略 Core Web Vitals（LCP/CLS/INP），只改文案而不解决性能瓶颈。
- 跳过标题层级（如 h1 直接到 h3），破坏内容结构语义。
- 遗漏 canonical 或指向错误 URL，导致重复内容与收录分散。
- 只审首页，忽视分页、筛选页与 noindex 页面的 SEO 处理。

## 注意事项
- 只修复检查命令报告的失败项，不要顺手大面积改写内容。
- noindex 与 canonical 的调整需符合真实意图，不得为消除告警而误屏蔽页面。
- 性能问题优先从根本（资源体积、渲染阻塞）解决，而非调参掩盖。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
