# 社媒帖子生成器

**分类:** 内容创作与写作
**标识符:** `social-post-generator`
**最大迭代次数:** 10

## 目标

为每个目标平台生成符合其长度、格式与调性规范的社媒帖子，保留同一核心信息但按平台差异分别呈现。成功标志是检查命令确认所有平台均已生成合规帖子。

## 适用场景

当一条内容需要适配并分发到多个平台（如短文、长文、带标签等不同形态）时使用。

## 检查命令

```bash
python scripts/check_posts.py
```

## 退出条件

- 每个目标平台均已生成帖子。
- 每条帖子的字符数、标签、链接与媒体格式均符合对应平台限制。
- 核心信息在所有平台间保持一致。

## 执行步骤

Step 1: 运行检查命令，捕获缺失的平台与每条帖子的合规问题（超长、缺标签、格式不符等）。
Step 2: 逐平台分析——对照该平台的长度上限、换行/标签习惯、媒体要求与调性规范，找出不达标项。
Step 3: 为缺失平台生成帖子，或将不合规帖子改写为符合该平台规范；逐平台独立处理，不做逐字跨平台搬运。
Step 4: 重新运行检查命令；若仍有平台缺失或不合规且未达到最大迭代次数，回到 Step 2。
Step 5: 若达到最大迭代次数仍未全部覆盖，停止并报告剩余平台与未解决项，不得无限循环。

## 常见陷阱

- 将同一条文案逐字发到所有平台，忽视各平台的长度与调性差异。
- 为凑标签而堆砌无关话题标签，触发平台限流或显得低质。
- 误判字符统计口径（按代码点而非显示宽度，或忽略链接折算），导致实际超长。
- 忽视媒体格式/比例要求，导致图片被裁切或上传失败。

## 注意事项

- 各平台帖子独立生成，核心信息一致但表达按平台定制。
- 不编造数据、引用或第三方背书。
- 遵守各平台的内容规范与字数限制，生成前确认目标平台清单。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
