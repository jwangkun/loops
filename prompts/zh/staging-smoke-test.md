# 预发布冒烟测试

**分类:** 测试
**标识符:** `staging-smoke-test`
**最大迭代次数:** 5

## 目标

在预发布环境中运行冒烟测试套件，确认所有关键路径（登录、核心业务流、支付/数据写入等）均能正常返回，且测试进程以退出码 0 结束。成功意味着最近一次部署的镜像确实在类生产环境中可用。

## 适用场景

代码已合并并部署到预发布环境后、正式发布前使用；用于在流量切换前快速验证核心功能是否受本次变更影响。

## 检查命令

```bash
npm run smoke:staging
```

## 退出条件

- `npm run smoke:staging` 退出码为 0。
- 输出中无失败用例、无跳过（skip）用例、无错误日志中的 5xx 或超时。
- 失败用例数稳定为 0（不是被注释或跳过所得）。

## 执行步骤

Step 1: 运行检查命令，完整捕获 stdout/stderr 与退出码。
Step 2: 解析失败项：区分环境问题（依赖服务未起、网络、配置/密钥缺失、数据库未迁移）与应用缺陷（断言失败、接口返回错误）。优先怀疑环境，因为冒烟测试依赖真实下游。
Step 3: 针对根因做最小修复：环境/配置类修复预发布配置或迁移，应用类修复对应代码。不要通过放宽断言、跳过用例或注释检查来"变绿"。
Step 4: 重新运行检查命令；若仍有失败且未超过最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代仍未通过时停止，列出剩余失败项及其根因，并明确标注哪些是环境问题、哪些是代码缺陷。不要无限循环。

## 常见陷阱

- 预发布依赖服务（数据库、缓存、第三方 API）未就绪即运行，导致大量误报失败。
- 测试命中了真实第三方 API 但密钥/额度未配置，错误地被当作代码缺陷修复。
- 用 `|| true`、`.skip` 或放宽断言让套件变绿，掩盖真实回归。
- 缓存了上一次的失败结果，未重新运行即误判通过。

## 注意事项

- 仅在预发布环境执行，禁止对生产环境做写操作类冒烟。
- 修复仅限本次失败涉及的配置/代码，不顺带重构无关测试。
- 涉及密钥变更时，确认是预发布密钥而非生产密钥。
