# 翻译审校循环

**分类:** 内容创作与写作
**标识符:** `translation-review-loop`
**最大迭代次数:** 10

## 目标

让译文在准确、流畅、符合目标语境三方面全部通过 `translation_check.py`。每一稿仅针对检查报告的具体片段做最小修改——纠正误译、消除机翻腔、对齐术语与语气——而非通篇重译。成功即检查零问题且语义与原文一致。

## 适用场景

在本地化或跨语言交付（UI 文案、文档、营销内容）时使用，尤其当存在目标语种、地区习惯或品牌术语表时。

## 检查命令

```bash
python scripts/translation_check.py
```

## 退出条件

- `translation_check.py` 退出码 0，无未解决问题。
- 无误译、漏译或过度意译。
- 术语、语气与目标地区习惯一致。

## 执行步骤

Step 1: 运行检查，完整捕获输出（按片段列出的误译、生硬表达、术语不一致、长度溢出等）。
Step 2: 逐条分析失败：区分机械直译丢失习语、地区用语错误、术语不统一、UI/排版长度溢出；定位到具体片段与原因。
Step 3: 用最小改动重写该片段，遵循术语表与目标地区习惯，不掩盖或跳过问题。
Step 4: 重新运行检查；若仍失败且未达最大迭代次数，回到 Step 2。
Step 5: 达到最大迭代仍未通过则停止，报告剩余阻塞项（片段、问题类型、原文与译文），不要无限循环。

## 常见陷阱

- 逐字直译丢失习语、双关或语气，让译文生硬甚至误导。
- 只对齐语言（如"西班牙语"）却忽略地区（卡斯蒂利亚 vs 拉美），用词习惯不符。
- 术语前后不统一，或脱离既定术语表自造译法。
- 译文长度溢出 UI 容器却仍标记为通过，破坏排版。

## 注意事项

- 地区与术语表由需求方提供；缺失时先确认，不要自行假设。
- 保留原文的事实、数字与品牌口径，不杜撰或本土化改写数据。
- 涉及法律/医疗/合规等高风险内容时，改动需可追溯。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
