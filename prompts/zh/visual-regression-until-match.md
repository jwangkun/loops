# 视觉回归直到匹配

**分类:** 测试
**标识符:** `visual-regression-until-match`
**最大迭代次数:** 6

## 目标

让带 `@visual` 标记的视觉回归测试通过，退出码为 0。所有像素差异中，仅保留有意为之的设计变更（需更新基准）；无意差异必须修复产品代码或样式，使其回到基准。

## 适用场景

UI 重构、组件改动或设计系统升级后，视觉快照出现差异，需要区分"有意的样式变更"与"意外的回归"，并分别处理时。

## 检查命令

```bash
npx playwright test --grep @visual
```

## 退出条件

- `npx playwright test --grep @visual` 退出码为 0。
- 所有视觉用例匹配基准；任何基准更新都对应明确、有意的设计变更。
- 未达到最大迭代次数上限。

## 执行步骤

Step 1: 运行 `npx playwright test --grep @visual`，收集每个失败用例的 diff 报告、期望/实际截图与影响范围。
Step 2: 逐个判定差异：有意的设计变更 → 准备更新基准；意外回归 → 定位组件/样式/布局根因。忽略抗锯齿/字体渲染等无关噪声。
Step 3: 意外差异做最小样式或组件修复使其回到基准；有意变更才更新对应快照基准，并附变更理由，绝不批量 approve。
Step 4: 重新运行该命令；若仍有差异且未达上限，回到 Step 2。
Step 5: 若达到最大迭代次数仍有未消解差异，停止并报告每个剩余差异（有意/意外判定、影响组件、截图链接）；绝不无限循环。

## 常见陷阱

- 基准漂移：批量更新快照让真实回归被永久掩盖。
- 忽略环境差异：字体、抗锯齿、视口、动画时序在不同机器上产生假阳性。
- 把布局回归当噪声：尺寸/间距差异往往是真实回归，不应草率放过。

## 注意事项

- 不要批量 approve 所有差异来快速通过。
- 基准更新必须逐一对应有意的、经过评审的设计变更。
- 优先修复产品代码回到现有基准；仅当设计确有变更时才更新基准。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
