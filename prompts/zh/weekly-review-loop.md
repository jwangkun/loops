# 每周回顾循环

**分类:** 效率与生产力
**标识符:** `weekly-review-loop`
**最大迭代次数:** 3

## 目标

产出一份反映本周真实情况的周回顾报告：涵盖成就、阻塞、目标进展与下周具体计划，校验脚本通过。成功意味着报告基于本周实际数据而非空泛模板，可直接用于复盘与规划。

## 适用场景

在一周结束时使用，用于复盘本周进展并规划下周。

## 检查命令

```bash
python scripts/weekly_review_check.py
```

## 退出条件

- 报告涵盖目标进展、本周任务与下周计划三大板块。
- 成就与阻塞基于本周实际记录，非占位符。
- 下周计划有明确事项，非空泛套话。

## 执行步骤

Step 1: 运行 `python scripts/weekly_review_check.py`，捕获缺失板块（目标进展/任务/下周计划）或仍是占位符、空泛套话之处。
Step 2: 分析缺口——定位只有占位符未填实际数据的部分、只罗列任务却未对照目标评估进展、以及下周计划缺少具体事项或责任人的问题。
Step 3: 做最小修复：用本周真实成就/阻塞填充内容、对照目标评估进展、把下周计划写成具体可执行事项，绝不靠复制模板套话凑过校验。
Step 4: 重新运行校验；若仍有缺失且未达最大迭代次数，回到 Step 2。
Step 5: 若达到最大迭代次数仍未通过，停止并报告剩余阻塞项（如本周记录缺失、无法评估进展），不要无限循环。

## 常见陷阱

- 用通用模板填占位符，内容不反映本周实际。
- 只罗列完成任务，不对照目标评估真实进展。
- 下周计划空泛（如"继续推进"），无具体事项或日期。
- 回避或轻描淡写本周的阻塞与未完成项。

## 注意事项

- 内容必须基于本周真实记录，不得臆造成就或隐瞒阻塞。
- 目标进展要量化（完成度百分比/里程碑），便于纵向对比。
- 下周计划事项应可执行、可验收，与本周遗留阻塞衔接。

- 收敛保护：若同一检查以相同根因连续两次迭代失败，应更换思路或停止上报，而非机械地原样重试。
- 预算纪律：遵守宿主 harness 的 token / 成本 / 时间预算；预算耗尽视为「停止并上报」信号，而非重试信号。
- 终态明确：循环只能以「成功 / 受阻 / 耗尽」三种终态结束；停滞或预算耗尽绝不能被报告为成功。
